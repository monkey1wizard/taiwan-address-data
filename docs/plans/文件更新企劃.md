# 文件更新企劃

日期：2026-10-12。

本企劃整理 `taiwan-address-data` 的文件，讓讀者能找到資料使用方式、政府資料更新步驟，以及目前已知的問題。2026-10-12 已依使用者確定的範圍完成整理，D-1 至 D-6 的文件檢查通過。修改內容與檢查證據見[執行紀錄](../records/2026-10-12-文件整理.md)。程式修正及真實資料驗收不在本次完成範圍。

## 範圍

- 目前只處理政府提供的地址資料，說明政府公布資料後，本專案如何下載、檢查及更新檔案。
- 整個專案只有根目錄一份 `README.md`。不新增 `docs/README.md` 或其他 README。
- 使用簡單的話，直接說明檔案用途、操作步驟與限制。
- `taiwan-lvr-geodata` 寫入的更新暫不處理，等那邊成功後才考慮。
- 現有 `supplements/`、相關程式與 `docs/supplements.md` 先保留，不列入本次整理，也不作為政府資料更新的必要步驟。
- 本次工作只整理文件，不修改程式、排程設定或地址資料，不執行真實下載、更新或發布。

## 要修改的內容

### 根目錄 README

保留專案用途、資料來自政府的說明、程式授權及基本使用方式。詳細操作和格式移到對應文件，根目錄只保留摘要與連結。

- 分清楚「已有這個縣市的資料」與「程式支援自動更新這個縣市」。不能把未支援自動更新寫成沒有資料。
- 說明政府資料的日期與本專案下載日期不同，不再使用意義不明的「最後更新日」。
- 移除「整批取代是安全的」等過度保證，改為目前已有的檢查與仍存在的限制。
- 核對查詢介面的實際啟動方式與外部套件需求，不直接承諾開啟 HTML 就能離線使用。
- 不把 `supplements/` 的操作列入目前主要使用流程。若保留入口，只標明暫不處理。
- 加入資料格式、更新說明、已知問題與本企劃的連結。新增文件完成前，不放入無效連結。

### 資料格式說明

新增 `docs/data-format.md`，以程式和既有 CSV 為依據。

- 說明 `roads/`、`road.csv`、`area_*.csv`、`update_log.csv` 的用途。
- 列出路檔的 14 個欄位，解釋哪些是代碼、哪些是地址文字，空值如何表示。
- 說明行政區代碼須保留前導零，`COUNTY`、`TOWN`、`VILLAGE` 不能直接以中文名稱代替。
- 說明輸出欄位 `X` 為經度、`Y` 為緯度。程式雖有預設座標系統，各政府原始檔是否適用仍須查證。
- 說明檔名規則、無路名的檔案，以及路檔更新後需要同步更新 `road.csv`。
- 分開描述前端載入行政區檔的優先順序，以及更新器實際讀取哪些行政區檔。兩者目前不同，不能合寫成相同行為。
- 說明 `update_log.csv` 的 `last_updated` 目前記錄本專案執行日期，不能當作政府資料產製日期。

### 政府資料更新說明

改寫既有 `docs/automated-update.md`，保留原路徑。

- 刪除「目前沒有 CI」等過期敘述。
- 移除整份 workflow 的複本，改為連到實際 YAML。文件保留讀者需要的操作與排查說明。
- 依 `update_addresses.py` 的設定列出縣市、政府資料集編號或下載頁，以及下載格式。未重新查證的連結與發布頻率要註明。
- 列出安裝需求及現有命令，包括 `--list`、指定縣市、`--updated-only`、`--all`。
- 說明 `--updated-only --dry-run` 會連線查詢更新資訊，但不下載地址檔。不能把它寫成完全離線，也不能把單獨 `--dry-run` 當作通用保護。
- 說明有些縣市在無法查到更新日期時仍會被選取，不寫成「只下載確定有更新的縣市」。
- 說明先下載及處理資料、通過現有檢查後刪除舊路檔、寫入新檔，再更新索引和紀錄的實際順序。
- 明確列出限制：寫檔中途失敗沒有完整復原保證，workflow 也可能提交部分變更。不要把例外捕捉寫成失敗資料一定不會發布。
- 分開說明本機更新與 GitHub Actions 更新。排程、通知與保活功能依實際設定描述，不承諾準時執行或一定寄達通知。
- 查證外部平台規則時記下官方文件與查證日期。未查證的說法保留為待確認，不直接沿用舊文件。

### 執行紀錄

文件整理完成後，在 `docs/records/` 記錄修改檔案、依據版本、執行命令及結果。使用 `pass`、`fail`、`not-run` 區分通過、失敗及未執行。

文件檢查通過不代表程式問題已修正，也不代表真實資料已通過驗收。若未執行政府下載、座標修正、全量地址檢查或公開發布，必須明列未執行。

## 文件檢查方式

- 盤點專案內所有大小寫形式的 README，只能保留根目錄那一份。
- 檢查 Markdown 相對連結、表格、標題與範例路徑。規劃中的檔案在建立前使用文字表示，不建立無效連結。
- 將每項命令與程式參數核對。需要下載、改寫檔案、建立 Issue 或發布的命令只核對，不為了文件檢查直接執行。
- 對照程式與 YAML，核對成功、部分成功、失敗三種情況，不能只描述順利執行的結果。
- 檢查繁體中文用詞，避免沒有解釋的新名詞。
- 檢查 Git 差異，確認只涉及本企劃列出的文件，沒有改動 CSV、程式、workflow 或暫不處理的檔案。
