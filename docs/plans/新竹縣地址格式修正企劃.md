# 新竹縣地址格式修正企劃

日期：2026-10-13。

本企劃處理新竹縣路檔的門牌格式問題。2026-10-13 `taiwan-lvr-geodata` 擁有者決定：修正在本專案的資料來源端進行，下游不另加解析規則。修正完成並更新版本後，下游重新釘選本專案的提交。

## 問題

固定版本 `3ff9be0265b22a4910abf2bd4e3e96c7653fb6f0` 中，新竹縣（縣市代碼 `10004`）262,762 列門牌全部無法依下游地址規則建立地址鍵。範例 `FULL_ADDR`：`新竹縣竹北市中興里7鄰19之8I-`。兩個特徵：

- 門牌主號後沒有「號」。
- 結尾多出一個大寫英文字母加連字號，目前看到 `I-`、`G-`、`H-`。

其他 21 個縣市的路檔沒有這個格式。證據見[已知問題](../known-issues.md)「新竹縣地址格式」。

## 待查

1. `I-`、`G-`、`H-` 的意義。可能來自政府原始檔的某個欄位，也可能是更新器組合 `FULL_ADDR` 時誤接欄位。先比對政府原始下載檔與 `scripts/update_addresses.py` 的新竹縣處理分支。
2. `NUMBER` 欄的值是否同樣缺「號」，或只有 `FULL_ADDR` 受影響。
3. 問題是否只在這個資料版本，或每次月更新都會重現。

## 工作

| 卡片 | 內容 | 驗收 |
| --- | --- | --- |
| H-1 | 用本機新竹縣路檔與政府原始檔抽樣比對，確認 1 至 3 的答案，寫入本企劃 | 原因有證據，不是推測 |
| H-2 | 依原因修正更新器的新竹縣處理，不手改路檔 | 重跑新竹縣更新後，抽樣列的 `FULL_ADDR` 有「號」、沒有多餘字母；其他縣市輸出不變 |
| H-3 | 更新 `update_log.csv`、`road.csv`，記錄新版本提交 | 下游以新提交重新釘選後，新竹縣可建立地址鍵的列數不再是 0 |

## 不做

- 不在下游 `taiwan-lvr-geodata` 加去尾或補「號」的解析規則。
- 不在不知道原因的情況下用字串規則整批改寫路檔。

## 下游影響

修正前，下游離線索引沒有新竹縣有效門牌，新竹縣交易只能靠 TGOS 定位。修正後下游要重新釘選版本並重跑離線階段。
