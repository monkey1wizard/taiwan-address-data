# 資料格式

本文件說明政府門牌資料在本專案中的檔案用途與欄位。欄位和範例依更新器及現有 CSV 核對，沒有重新下載政府資料。

## 檔案

| 檔案 | 用途 |
| --- | --- |
| `roads/{縣市代碼}-{道路名}.csv` | 儲存該縣市該道路的門牌資料。沒有道路名時，檔名可為 `{縣市代碼}-.csv`。 |
| `road.csv` | 列出路檔中的縣市代碼和道路名，供前端查找路檔。路檔更新後要重建索引。 |
| `area_*.csv` | 前端用來將行政區名稱對應至代碼。 |
| `update_log.csv` | 記錄更新器處理的縣市、列數和執行日期。 |

`road.csv` 可用 `python scripts/build_road_index.py` 重建。更新器也會在縣市更新後呼叫索引程式。

## 路檔欄位

路檔使用 UTF-8 CSV，欄位依序如下：

| 欄位 | 內容 |
| --- | --- |
| `FULL_ADDR` | 完整地址文字 |
| `COUNTY` | 縣市代碼 |
| `TOWN` | 鄉鎮市區代碼 |
| `VILLAGE` | 村里代碼 |
| `NEIGHBORHOOD` | 鄰文字 |
| `ROAD` | 路名文字 |
| `SECTION` | 段文字 |
| `LANE` | 巷文字 |
| `ALLEY` | 弄文字 |
| `SUB_ALLEY` | 保留的地址欄位，目前更新器寫入空值。舊資料有值時不得自行忽略或改寫 |
| `TONG` | 保留的地址欄位，目前更新器寫入空值。舊資料有值時不得自行忽略或改寫 |
| `NUMBER` | 號及其後文字 |
| `X` | 經度欄位 |
| `Y` | 緯度欄位 |

欄位順序可在 `scripts/update_addresses.py` 的 `CSV_HEADER` 核對。空值以空欄表示。縣市、鄉鎮市區及村里代碼是識別值，處理時要保留前導零，不要改成中文名稱。`COUNTY`、`TOWN`、`VILLAGE` 不可互相替代。

代碼格式例如 `COUNTY=63`、`TOWN=6300400`、`VILLAGE=6300400-006`。直轄市縣市代碼是 2 碼，其他縣市是 5 碼，例如金門 `09020`。鄉鎮市區代碼是 7 碼，村里代碼是鄉鎮市區代碼加上連字號與 3 碼村里序號。這些是格式示例，不是門牌資料。更新器找不到村里對照時會寫入 `{鄉鎮市區代碼}-000`，不代表已確認實際村里。

程式設定的預設來源座標系統為 EPSG:3826，各原始檔是否適用仍須查證。更新器將座標轉為 WGS84，輸出欄位定義為 `X` 經度、`Y` 緯度。欄位定義不代表既有每一列座標都已驗證，已知限制見[已知問題](known-issues.md)。

## 檔名與道路索引

更新器會把 Windows 檔名不允許的字元換成底線，並移除檔名結尾的空白和句點。CSV 的 `ROAD` 欄仍保留道路文字。如果不同路名清理後變成同一檔名，更新器會把資料寫進同一檔案。

`road.csv` 的欄位是 `county_id,road`，由實際路檔的檔名產生。索引道路名可能經過檔名清理，不一定等於 CSV 的原始 `ROAD` 文字。沒有道路名時，路檔使用 `{縣市代碼}-.csv`，索引的 `road` 欄為空。

## 行政區檔

行政區檔的欄位是 `name,dgbas_id`，將名稱對應至行政區代碼。前端取得各檔後，按 `custom > 2015 > 2014 > 2010 > 1984` 決定同名資料的優先順序，不受各檔下載完成先後影響。舊年份檔保留歷史名稱對照。

更新器僅使用 `area_2014.csv` 取得行政區與村里名稱對照。`build_area_2015.py` 另從既有路檔抽取名稱對照，與 2014 檔比較後合併寫入 `area_2015.csv`。所以不能把目前做法寫成「年份檔建立後永遠不改」或「前端與更新器讀相同對照」。

## 日期

`update_log.csv` 的 `last_updated` 是更新器執行當日的本機日期。它不是政府資料的發布日或產製日，也不能單獨證明來源資料有更新。

此檔欄位是 `code,county,records,last_updated`，依序為縣市代碼、縣市名稱、該次寫入列數及執行日期。

程式依據：[更新器](../scripts/update_addresses.py)、[道路索引](../scripts/build_road_index.py)、[行政區對照產生程式](../scripts/build_area_2015.py)、[前端查詢](../address.js)。
