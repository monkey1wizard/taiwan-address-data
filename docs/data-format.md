# 資料格式

讀取路檔時，請依本文件解釋欄位、代碼與處理規則。本文件依本機程式與對照表整理，不代表已逐列驗證所有資料。操作命令見[政府資料更新](automated-update.md)，資料品質限制見[已知問題](known-issues.md)。

## 檔案

| 檔案 | 用途 |
| --- | --- |
| `roads/{縣市代碼}-{道路名}.csv` | 儲存該縣市該道路的門牌資料。沒有道路名時，檔名可為 `{縣市代碼}-.csv`。 |
| `road.csv` | 列出路檔中的縣市代碼和道路名，供前端查詢路檔。路檔更新後要重建索引。 |
| `area_*.csv` | 前端用來將行政區名稱對應至代碼。 |
| `update_log.csv` | 記錄更新器處理的縣市、列數和執行日期。 |
| `char_fixes.csv` | 還原政府資料中缺字的對照表，見「缺字與字碼」。 |
| `rare_chars.csv` | 本專案用到的非 Big5 罕用字，以及各來源異寫對應的標準字。 |

索引由工作樹中的路檔產生。若 Git 追蹤的檔案未出現在工作樹，索引可能缺列。重建方式與處理限制見[政府資料更新](automated-update.md#本機維護)。

## 路檔欄位

路檔使用 UTF-8 CSV，欄位依序如下：

| 欄位 | 內容 |
| --- | --- |
| `FULL_ADDR` | 完整地址文字 |
| `COUNTY` | 縣市代碼 |
| `TOWN` | 鄉鎮市區代碼 |
| `VILLAGE` | 村里代碼 |
| `NEIGHBORHOOD` | 鄰文字 |
| `ROAD` | 路名文字 |
| `SECTION` | 段文字 |
| `LANE` | 巷文字 |
| `ALLEY` | 弄文字 |
| `SUB_ALLEY` | 保留的地址欄位，目前更新器寫入空值。舊資料有值時不得自行忽略或改寫 |
| `TONG` | 保留的地址欄位，目前更新器寫入空值。舊資料有值時不得自行忽略或改寫 |
| `NUMBER` | 號及其後文字 |
| `X` | 經度欄位 |
| `Y` | 緯度欄位 |

欄位順序可在 `scripts/update_addresses.py` 的 `CSV_HEADER` 核對。空值以空欄表示。縣市、鄉鎮市區及村里代碼是識別值，處理時要保留前導零，不要改成中文名稱。`COUNTY`、`TOWN`、`VILLAGE` 不可互相替代。

代碼格式例如 `COUNTY=63`、`TOWN=6300400`、`VILLAGE=6300400-006`。直轄市縣市代碼是 2 碼，其他縣市是 5 碼，例如金門 `09020`。鄉鎮市區代碼是 7 碼，村里代碼是鄉鎮市區代碼加上連字號與 3 碼村里序號。這些是格式示例，不是門牌資料。更新器找不到村里對照時會寫入 `{鄉鎮市區代碼}-000`，不代表已確認實際村里。

`NUMBER` 欄保留來源「號」欄的內容，可能包含樓層或戶政註記，例如「32號二樓」「168號(捷運木柵線六張犁站)」。

## 座標與精度

更新器將來源座標轉為 WGS84，輸出 `X` 經度與 `Y` 緯度，均保留小數 9 位。這是文字格式，不是定位精度，也不保證不同平台輸出完全相同。

程式預設來源為 EPSG:3826，也就是 TWD97 121 度分帶。澎湖縣與金門縣設定為 EPSG:3825，也就是 119 度分帶。新增來源時，必須依該來源的規格確認座標系統，不應只按縣市名稱推定。

2026-10-14 的[門牌與村里紀錄](records/2026-10-14-門牌與村里.md)記載，Windows 與 GitHub 主機有 1 列緯度在第 9 位小數相差 1。此紀錄不代表本次重新驗證所有座標。

## 地區欄與套用順序

來源的「地區」欄可能是聚落或巷名，例如「十甲巷」「信義新村」。輸出沒有獨立地區欄，更新器將地區接在巷名前面，合併至 `LANE`。巷欄為空時，合併結果只有地區文字。新竹市從整段地址解析欄位，不使用這項地區合併。

分欄來源依下列順序處理：

1. 讀取來源欄位，套用來源字元對照與文字正規化。
2. 套用 `village`、`street`、`lane` 規則，再建立單一門牌規則使用的鍵。
3. 套用單一門牌修正。若有 `plate_area`，直接使用其地區值，包括空值。
4. 若沒有 `plate_area`，以原鄉鎮市區代碼及正規化後的來源地區值查詢 `area` 規則。來源地區為空時不查詢。
5. 將處理後的地區接在處理後的巷名前面，再查村里代碼並組成地址。

因此，`lane` 的鍵不含後來合併的地區。`area` 修正同鄉鎮內相符的地區值，`plate_area` 只指定單一門牌，且優先於 `area`。

## 門牌去重規則

更新器以欄位與座標判斷是否刪除重複列，不保證每個地址文字只剩一列。規則實作於 `dedupe_door_plates`：

| 判斷 | 規則 |
| --- | --- |
| 分組 | `TOWN`、`VILLAGE`、`NEIGHBORHOOD`、`ROAD`、`SECTION`、`LANE`、`ALLEY` 及號欄拆出的門牌部分都相同，才放入同組。 |
| 樓層 | 號欄符合程式的「N樓」或「N樓之N」格式時，以「號」為止的文字分組。其他尾端文字保留在分組鍵內。 |
| 保留順序 | 優先處理沒有樓層的列，其次是最低樓層，再其次是最小之號。條件相同時按原始列順序。 |
| 刪除條件 | 同組中，與任一已保留列的估算距離小於 10 公尺才刪除。距離等於或大於 10 公尺仍保留。 |
| 座標例外 | 座標無法解析為數字時，去重函式保留該列。這不代表更新器會接受無法解析的來源座標，來源處理階段另有檢查。 |

例如「32號」「32號二樓」「32號二樓之1」可分在同組。只有符合距離條件時，才會保留「32號」而刪除其他兩列。若沒有不帶樓層的列，可能保留「32號二樓」。

「107號(土坂派出所)」保留註記作為分組鍵的一部分，不會與「107號」分在同組。村里或鄰不同的同號門牌也不會分在同組。這些規則不能證明建物或地址身分相同。

## 檔名與道路索引

更新器會把 Windows 檔名不允許的字元換成底線，並移除檔名結尾的空白和句點。CSV 的 `ROAD` 欄仍保留道路文字。如果不同路名清理後變成同一檔名，更新器會把資料寫進同一檔案。

`road.csv` 的欄位是 `county_id,road`，由實際路檔的檔名產生。索引道路名可能經過檔名清理，不一定等於 CSV 的原始 `ROAD` 文字。沒有道路名時，路檔使用 `{縣市代碼}-.csv`，索引的 `road` 欄為空。

## 行政區檔

行政區檔的欄位是 `name,dgbas_id`，將名稱對應至行政區代碼。前端取得各檔後，按 `custom > 2015 > 2014 > 2010 > 1984` 決定同名資料的優先順序，不受各檔下載完成先後影響。舊年份檔保留歷史名稱對照。

更新器用 `area_2014.csv` 與 `area_2015.csv` 對照村里名稱與代碼。兩檔有同名不同代碼時，以 2014 檔為準。區名只取自 2014 檔，所以 `FULL_ADDR` 的區名維持 2014 年的寫法，例如「員林鎮」。

`area_2015.csv` 收錄 2014 年之後新設或改名的村里。2026-10-14 以國土測繪中心村里清單補齊，代碼規則為鄉鎮市區代碼加上村里序號，與 `area_2014.csv` 的編法相同。`build_area_2015.py` 是較早從路檔抽取對照的腳本，不會依國土測繪中心清單補齊。

## 缺字與字碼

更新器讀入來源時，會去掉村里、路名與巷名中只包住一個漢字的括號，例如「(塭)南里」改成「塭南里」，「[萡]子村」改成「萡子村」。括號裡超過一個字的不處理，例如號欄註記「(土坂派出所)」，或以部件描述一個字的「石[石曹]里」。

政府匯出檔會把系統無法儲存的字寫成佔位字元。

- 「?」來自 Big5 匯出，原字通常不在 Big5 內。
- 「■」與全形「？」也出現在 Unicode 來源，可能代替一般字，例如樓層的「樓」。

分欄來源讀入時，更新器先套用 `rare_chars.csv` 中對應來源的字元轉換，再做 NFC 正規化。可依 NFC 對應的相容表意字會轉換，未列入來源對照的私用區字元仍保留。不要把正規化視為所有缺字均已還原的保證。

`char_fixes.csv` 的欄位是 `county,town,field,source_value,fixed_value,evidence,checked_on`。鍵是縣市代碼、鄉鎮市區代碼、欄位與來源值。同一個來源值在不同鄉鎮可能對應不同的字，所以不能只看文字。

| `field` | 對象 | 鍵的來源值 |
| --- | --- | --- |
| `village` | 村里名 | 來源村里名 |
| `street` | 路名與段 | 路名加段 |
| `lane` | 巷名 | 地區合併前的巷名 |
| `area` | 地區 | 正規化後的來源地區值，依原鄉鎮市區代碼查詢 |
| `number` | 單一門牌的號欄 | 路名、段、巷、弄與號欄串接 |
| `neighborhood` | 單一門牌的鄰 | 同 `number`，取還原前的號欄 |
| `drop` | 刪除單一門牌的整列 | 同 `number` |
| `plate_village` | 單一門牌的村里名 | 同 `number` |
| `plate_town` | 單一門牌的鄉鎮市區代碼 | 同 `number`。新代碼決定 `TOWN`、`FULL_ADDR` 的區名與村里代碼 |
| `plate_street` | 單一門牌的路名與段 | 同 `number` |
| `plate_area` | 單一門牌的地區欄 | 同 `number`。空值表示不使用地區 |
| `full_addr` | 只改 `FULL_ADDR` 中的文字 | 要替換的文字，只供 `fix_static_roads.py` 使用 |

更新器的單一門牌規則，在一般村里、路名與巷名修正之後建立鍵，在單一門牌修正之前固定鍵值。即使 `plate_town` 改了鄉鎮市區，規則仍以原鄉鎮市區代碼查詢。

單一門牌的欄位，鍵可以寫成「村里|鄰|路名、段、巷、弄與號欄」。更新器先找含村里與鄰的鍵，找不到才用不含村里與鄰的鍵。`number` 的修正值須保留該鍵的路名、段、巷與弄組成的開頭文字，更新器才會取其後的文字替換號欄。沒有路名的門牌，例如「6鄰1號」，必須用含村里與鄰的鍵，以免套用到其他村的同號門牌。

`fix_static_roads.py` 使用另一套直接處理路檔的流程，不支援更新器的所有單一門牌規則。使用範圍見[政府資料更新](automated-update.md#缺字修正)。

`evidence` 記錄每列的依據，例如官方清單唯一相符、2016 年路檔同位置、交易資料或擁有者確認。依擁有者改寫的列，還原值不一定只是補字，可能刪除或改寫文字。

`rare_chars.csv` 的欄位是 `source,form,form_codepoints,standard,standard_codepoint,block,evidence,checked_on`。`source` 為 `標準` 的列是本專案用到的非 Big5 漢字清單。其他列記錄某個來源的異寫，例如戶政司路名的私用區碼位或相容表意字，對應到標準字。

`area_2014.csv` 有少數異體字雙列，例如「南瑤里」與「南瑶里」對到同一村里代碼，讓還原後的村里名能查到代碼。

## 日期

`update_log.csv` 的 `last_updated` 是更新器執行當日的本機日期。它不是政府資料的發布日或產製日，也不能單獨證明來源資料有更新。

此檔欄位是 `code,county,records,last_updated`，依序為縣市代碼、縣市名稱、該次寫入列數及執行日期。
